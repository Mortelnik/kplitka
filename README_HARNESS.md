# Установка минимального harness

Это дополнение к каркасу 0.2 с уже применённым исправлением Windows UTF-8.
Все файлы добавляются; исходники, профили, pyproject.toml, uv.lock,
существующие тесты и workflow не заменяются.

## Применить на вашей Windows

1. Сохраните текущую работу в Git или сделайте резервную копию.
2. Остановите агентов, редактирующих проект.
3. Распакуйте архив в `D:\Projects\kalitka-kp-plugin`.
   Дополнительной папки проекта внутри архива нет.
   Если AGENTS.md или другие одноимённые файлы уже созданы вами,
   не перезаписывайте их без сравнения и объединения.
4. Из корня проекта запустите:

```text
uv run python scripts/check.py --list
uv run python scripts/check.py
```

Повторные `uv init` и переустановка плагина не нужны.
Если dev-зависимости ещё не установлены: `uv sync --extra dev`.

Ожидание для переданного каркаса: lint PASS, package PASS, tests PASS
и 35 passed в `tests.log`. Если вы уже добавляли собственные тесты,
число будет отличаться. Путь к `report.json` печатается в терминале.

При ошибке пришлите конкретный лог из указанной папки; сначала проверьте,
что в нём нет секретов или реальных клиентских данных.
Скрипт возвращает ненулевой код, если хотя бы одна проверка не прошла.

## Файлы

- `AGENTS.md`: общие короткие инструкции всем агентам.
- `scripts/check.py`: фиксированные локальные проверки и JSON-отчёт.
- `tests/test_check_harness.py`: 15 новых тестов harness.
- `docs/harness/README.md`: рабочий процесс и предварительные роли моделей.
- `docs/harness/templates/TASK.md`: контракт задачи.
- `docs/harness/templates/IMPLEMENTATION_REPORT.md`: отчёт разработчика.
- `docs/harness/templates/REVIEW_REPORT.md`: отчёт проверяющего.
- `README_HARNESS.md`: эта инструкция.

## Первое сообщение каждому агенту

```text
Работай в указанной мной рабочей папке проекта.
Прочитай AGENTS.md и docs/harness/README.md.
Пока не меняй код. Подтверди путь, ветку, git status, доступные инструменты
и выбранную роль. Не запрашивай содержимое .env и ключи.
Дождись отдельного контракта задачи.
```

Разработка начинается после выдачи заполненного TASK.md.
Не направляйте несколько пишущих агентов в одну папку.

## Что проверено при подготовке

Локальный Linux Python 3.12: 35 тестов, Ruff и валидатор пакета проходят.
Проверены обработка ошибки, таймаута, отсутствующей команды,
UTF-8 логов, уникальность отчётов и фиксация Git-метаданных.
Проверка повторена после наложения дополнения на исходный каркас
с исправлением UTF-8. Нативный Windows-запуск дополнения ещё не выполнен;
он проверяется вами. Возможности ваших конкретных моделей не тестировались.

Это harness разработки, не готовый стенд оценки 40+ запросов
и не гарантия выполнения бизнес-ТЗ.

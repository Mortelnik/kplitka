# Р5.5. Сценарий демонстрации проекта

**Проект:** Kalitka AI — плагин генерации коммерческих предложений
**Ответственный:** Р5
**Продолжительность:** 5–7 минут
**Формат:** локальная демонстрация

## 1. Цель демонстрации

Показать структуру проекта, воспроизводимость установки, результаты автоматических проверок и возможность технической генерации DOCX.

Демонстрация отражает фактически проверенные возможности. Она не имитирует полноценную работу плагина в Kalitka AI.

## 2. Подготовка

Перед демонстрацией необходимо:

- открыть корневую папку проекта;
- убедиться, что установлены Python и uv;
- подготовить терминал PowerShell;
- убедиться, что доступны файлы учебного профиля и smoke-теста;
- подготовить просмотрщик DOCX.

Работа выполняется из корня репозитория.

## 3. Сценарий демонстрации

### Этап 1. Представление проекта — 40 секунд

Показать структуру репозитория:

- `src/kp_plugin/` — Python-код проекта;
- `plugins/fish-kp/` — пакет плагина;
- `profiles/` — профили компаний;
- `tests/` — автоматические тесты;
- `docs/` — документация.

Объяснить назначение проекта: подготовка коммерческих предложений на основе данных компании, расчётных механизмов и шаблона DOCX.

### Этап 2. Независимая установка — 1 минута

Показать команду:

```powershell
uv sync --extra dev --locked
```

Объяснить, что зависимости устанавливаются на основе lock-файла, обеспечивающего воспроизводимость окружения.

В качестве результата независимой установки показать подготовленное окружение Python 3.12.9 и установленный набор из 24 пакетов.

### Этап 3. Автоматические проверки — 1 минута

Запустить:

```powershell
uv run python scripts/check.py
```

Ожидаемый результат:

- `lint: PASS`;
- `package: PASS`;
- `tests: PASS`;
- код завершения 0.

Показать итоговый отчёт проверки в `out/checks/`.

Отдельно отметить, что автоматические тесты подтверждают проверенные программные сценарии, но не доказывают готовность интеграции с Kalitka AI.

### Этап 4. Техническая генерация DOCX — 2 минуты

Запустить:

```powershell
uv run python plugins/fish-kp/skills/generate-fish-kp/scripts/smoke_docx.py `
  --input plugins/fish-kp/skills/generate-fish-kp/assets/smoke-input.json `
  --output-dir out/smoke
```

Показать результат выполнения:

- `ok: true`;
- `mode: technical-smoke-only`;
- итоговая сумма: 2 200 000 RUB;
- путь к созданному DOCX.

Открыть полученный документ и показать его содержимое и структуру.

Пояснить, что пример использует синтетические данные и демонстрирует техническую генерацию документа, а не полноценный расчёт реального коммерческого предложения.

### Этап 5. Итоги — 40 секунд

Подвести итоги:

- независимая установка проекта подтверждена;
- штатные автоматические проверки завершились успешно;
- основные проверенные сценарии расчётного ядра работают;
- техническая генерация DOCX подтверждена;
- созданный документ успешно открывается.

Полная работа плагина через интерфейс Kalitka AI, взаимодействие с языковой моделью и передача готового КП пользователю требуют отдельной интеграционной проверки.

## 4. Контрольный список демонстрации

- [ ] Репозиторий открыт, структура проекта показана.
- [ ] Команда установки продемонстрирована.
- [ ] Результаты независимой установки объяснены.
- [ ] Штатная проверка запущена.
- [ ] Результаты lint, package и pytest показаны.
- [ ] Smoke-тест генерации DOCX запущен.
- [ ] Созданный DOCX открыт и показан.
- [ ] Ограничения технического примера проговорены.
- [ ] Итог демонстрации сформулирован.

## 5. Критерий успешной демонстрации

Демонстрация считается успешной, если все предусмотренные локальные этапы выполнены, результаты соответствуют ожидаемым, а ограничения текущей реализации представлены корректно.

**Важно:** демонстрация не должна представлять технический smoke-тест как полноценную генерацию коммерческого предложения через Kalitka AI.

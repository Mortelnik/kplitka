## Обновление B1/B2

В gate.py введены ConstraintStatus, ConstraintReview и constraint_review_fingerprint. CommercialAttestation.constraints опционален для совместимости вызовов, но его отсутствие/unknown блокирует коммерческий допуск. Review должен явно подтвердить отсутствие условий либо совместимость существующих условий с товаром, расчётом и условиями предложения; нужны источники и отпечаток полного текущего invocation и ответа P2. Неизвестные поля/явно неverified evidence не перекрываются review. Никакой интерпретации текста не добавлено. Только производная диагностика request.constraints может быть закрыта таким внешним свидетельством; остальные проблемы/неизвестные остатки продолжают блокировать. Исходные требования, evidence, неизвестные поля и диагностика сохраняются.

Legacy test_docgen.py теперь передаёт полный опубликованный вход P2. При локальной заглушке он вызывает checksum-проверенную fixture реального P2 вместо skip. tax_rate получен из уже существующего учебного эталона tax/base (20%), а не выбран как коммерческая ставка; вместимость 26 т соответствует существующим учебным входам. Проверки сумм/Decimal/источников сохранены и расширены. Код Юлии не менялся.

## Архитектура и интерфейсы

`raw_text → NeedsExtractor → CustomerNeeds → clarify → select_products → run_p2/prepare_p2_invocation → assess_selection → evaluate_gate → DOCX`.

P4 загружается отдельно `load_p4_catalog(catalog_path, stock_path, as_of, max_stock_age_days)`. Реальная calculate_offer инъецируется вызывающим компонентом. В production нет импорта tests или автоматической загрузки демонстрационных данных.

| Компонент | Реализованные входы → выходы | Проверка и ограничения | Зависимости команды |
|---|---|---|---|
| P3.1 needs.py | LLMClientProtocol.extract_needs(text) возвращает dict/JSON; NeedsExtractor.extract → CustomerNeeds с items, evidence, unknown_fields, model_payload, evidence_history | validate_partial допускает None; validate требует обязательные подтверждённые товар/количество/единицу. Проверяются типы/Decimal. Текстовое evidence — эвристика присутствия, не семантическое доказательство. Нет подключённого LLM/промптов/provider | Матвей: общий контракт и runtime; владелец: провайдер/допуски; P4: независимая оценка |
| P3.2 clarify.py | build_clarifications/determine_missing_fields; apply_clarification_answer → updated/clarify/invalid/conflict + новое состояние | 1-based позиции, ответы структурированы, копия состояния, история evidence. По умолчанию обязательны только product_name/quantity/unit; дополнительные required_fields поддержаны API, но orchestrator их не экспонирует | Политика обязательных полей и авторство ответа/согласия |
| P3.3 unreachable.py | HandlingRequest с Reason → handle_unreachable → UnreachableResult | conflict/insufficient_budget/product_unavailable/unknown_costs/missing_data; вопросы, объяснение, только внешние альтернативы. Из денежных операций — разница полного total и бюджета, не расчёт цен. VERIFIED требует externally_validated и полной стоимости; согласование изменений обязательно. Достоверность источников удостоверяет вызывающий компонент | P2: полная стоимость; Матвей: проверка ограничений и подтверждений |
| P3.4 selection.py | CustomerNeeds + tuple[CatalogProduct] + необязательные product_ids → SelectionResult | ID, нормализованное точное имя, только явные synonyms; draft в excluded; неоднозначность требует уточнения. Нет нечёткого поиска, конвертации единиц/подмен. Остатки/min/max — только совместимые величины; повторные SKU требуют joint_stock_allocation; свободные известные ограничения остаются непроверенными | Каталог, остатки и утверждённая политика ограничений |
| p4_catalog.py | Два конкретных CSV → P4Catalog(products, catalog_rows, stock_rows) | Сохраняет все поля, партии и диагностику, хеши файлов. Нет порога актуальности по умолчанию; synthetic/unknown/stale не суммируются как доступные. constraints_check остаётся unknown. Цены/правила не загружает | Евгений: версия набора, трактовка партий и происхождения; Матвей/Юлия: политика свежести |
| cases.py | Явные CaseLink, CaseRecord, product_ids и полное описание задачи → CaseMatch | verified/needs_review/unavailable. Коммерческий допуск: verified + allowed + нет permission_conflict + ручная проверка непустых usage_limits. Правило релевантности — точное полное описание, не ключевые слова. В P4 только related_cases, нет прочитанного полноценного справочника | Евгений: содержание/права/связи; Матвей: подтверждённый источник задачи |
| p2_adapter.py | P2Settings + текущие запрос/подбор/профиль + dict catalog/prices/rules + callable → P2Invocation/P2AdapterResult | Только одна позиция, т, однозначный подтверждённый ID. Отпечаток включает запрос, evidence, состав, входные снимки, скидки, версии профиля/прайса/P2, валюту и полноту. Нет формул цен. Ошибки непрозрачно сохранены. successful_calculation ≠ trusted_inputs ≠ complete_delivery_cost | Юлия: runtime-артефакт и границы API; Матвей: доверенная выдача свидетельств |
| selection_bridge.py | Подбор + профиль + внешние свидетельства расчёта/бюджета/доступности/кейсы → SelectionAssessment | Все позиции, bindings, проблемы, источники, P4 и снимок запроса сохраняются. Проблемы отдельно обрабатываются P3.3, rejected не означает доказанную недоступность. CaseMatch отдельно от Alternative. calculation_confirmed не равен готовности КП | Внешние проверенные факты, не текстовые ошибки P2 |
| docgen/gate.py | P2AdapterResult + текущий P2Invocation/None + assessment + CommercialAttestation/ConstraintReview → GateDecision | INTERNAL_DRAFT/COMMERCIALLY_APPROVED; повторная сборка контекста и assessment. B1 исправлен: неизвестные ограничения и отсутствие отдельного review блокируют, известные условия требуют внешней проверки совместимости. issuer не аутентифицируется. test_only не обходит gate | Матвей: доверенный issuer/актуальные входы/структурированная проверка ограничений |
| builder.py/corporate.py | Низкоуровневые dict, OfferPresentation или CorporateOffer → редактируемый DOCX | Старые интерфейсы сохранены. Реальный коммерческий путь проходит gate; цена за тонну из связанного прайса. Утверждённый A4/Arial/6 колонок; unknown-cost draft без фиктивной таблицы. Низкоуровневые renderer можно вызвать напрямую — это не авторизованный API выдачи КП | Подтверждённые реквизиты/условия через будущий production-адаптер |
| orchestrator.py | run_flow(text, extractor, answers, profile, settings, P2 callable, evidence…) → FlowResult | Последовательный локальный прогон, полные промежуточные результаты, безопасный выбор нового имени файла. Нет UI/API, хранения сессий, авторизации, конкурентного резервирования. В тестах FakeLLM и TEST ONLY, а P2 настоящий через fixture | Интеграционный runtime и управление жизненным циклом запроса |

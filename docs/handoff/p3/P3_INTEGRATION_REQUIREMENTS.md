## Что P2 подтверждает, а что должен предоставить вызывающий компонент

| Данные | Фактический источник | Что ещё нужно |
|---|---|---|
| product_id | Вход P2, в ответе есть только имя/источники | Точная связь с подтверждённой позицией и каталогом из selection |
| quantity/unit | quantity_tons на входе, единица не возвращается | Подтверждённые т, без неоговорённых преобразований; fingerprint |
| currency | Нет отдельного поля ответа; цена названа unit_price_rub_per_t | Согласованная валюта профиля/прайса/правил; никакой самостоятельной конвертации |
| profile ID/version | В P2 отсутствуют | Текущий авторизованный profile_id/version и снимок профиля |
| price snapshot/version | В P2 нет версии снимка | Реальный price_snapshot_id, source_ref/version/locator, актуальность |
| rules/discounts | Входные rules, стаж и requested_discount; результат discount_rule | Версия правил, подтверждённая применимость. Ядро выбирает лучшую скидку, имеет встроенные пороги 1 год/5 контейнеров; не исполняет произвольную декларативную политику |
| base/discount/tax/total | Реальный программный результат P2 | Проверенная версия исполняемого кода и достоверность входов; расчёт не является подтверждением прайса |
| delivery/additional costs | В ответе отсутствуют | Проверенные тарифы/полнота. Неизвестное не ноль; положительная доставка отдельно не входит в P2 total |
| stock/constraints | P2 это не подтверждает | Текущие партии/резервирование, внешняя проверка ограничений, сроки её действия |
| errors | Строка либо исключение | Пока хранить непрозрачно; для автоматической бизнес-классификации нужен структурированный API, не парсинг русского текста |
| multi-item | Нет общего многопозиционного вызова | Контракт полного заказа, общие скидки/логистика/остатки; не суммировать однопозиционные ответы самовольно |

## Требуется от Матвея (P1 / интеграционный runtime)

1. Утвердить общий контракт потребностей, выбранной позиции, снимка профиля/прайса/правил, результата расчёта, статусов и источников. Подтвердить роль локальных адаптеров; не заменять общие модели неявно.
2. Авторизовать issuer и источники: кто вправе выставить confirmed/trusted_inputs/externally_validated/scope_complete, на какой срок, для каких полей. Связать каждое подтверждение с точной версией/записью; не доверять source_id/хешу как свидетельству истинности.
3. Выдавать текущие входы и дату проверки; не повторно использовать старый P2Invocation. Привязать исполняемую P2 к зафиксированному артефакту, а не только строковому ярлыку p2_implementation.
4. Подключить реальный LLM/provider и версионированные промпты без передачи секретов в отчёты; согласовать обязательность deadline/address/budget/constraints и подтверждение существенных условий.
5. Экспонировать только gated коммерческий путь. Низкоуровневый builder/corporate остаётся техническим конструктором, его доступность не равна разрешению выдачи КП. Разделить INTERNAL_DRAFT, TEST ONLY и пользовательскую доставку документов.
6. Сессия уточнений/согласий, UI/chat-draft и служебная сводка; стратегия сохранения файлов, блокировки и резервирование остатков. Целевой skill/runtime пока не интегрирован с run_flow.

## Требуется от Юлии (P2)

1. Предоставить утверждённый runtime-артефакт/commit и способ импорта без копирования формул. Зафиксировать поддержку единиц, валюты, числовых типов и округления; отдельно согласовать обработку Decimal.InvalidOperation.
2. Подтвердить meaning total: включён ли НДС, доставка, прочие расходы; границы ставки налога/скидки, допустимость нулевой доставки. Текущий adapter не рассчитывает общий итог с положительной доставкой.
3. Утвердить лучшую/суммарную скидку, пороги стажа/объёма и контейнеров, сезонные правила. Предложения Матвея про 20 т/80% не равны опубликованному коду или согласованным правилам; P3 их не внедряет.
4. Согласовать структурированные ошибки и многопозиционный заказ, если они входят в следующий этап. Сейчас они не поддерживаются, должны оставаться безопасным отказом.
5. После интеграции проверить весь harness. B2 старого test_docgen.py закрыт полным учебным входом и вызовом настоящего ядра вместо skip; отдельная регрессия проверяет ветку локального импорта. Это не замена production wiring и не повод исправлять код Юлии.

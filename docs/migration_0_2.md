# Обновление каркаса без потери работы команды

## Если ещё не меняли старый каркас

Распакуйте новый архив в отдельную папку. Сравните её со старой и перенесите
изменения. Сохраните свою `.git`, реальные настройки remote и изменения команды.
Повторные `uv init` и `git init` существующему репозиторию не нужны.

## Если уже пишете код

1. Зафиксируйте текущую работу коммитом. Создайте ветку
   `chore/plugin-layout-0-2`.
2. Не заменяйте целиком `src/`, `profiles/`, `pyproject.toml` и `uv.lock`.
   Существующие бизнес-данные и код этой поставкой не обновляются.
3. Добавьте `.agents/plugins/marketplace.json`, `plugins/fish-kp/`,
   `tests/test_plugin_package.py`, `tests/test_issue_importer.py`,
   `scripts/import_issues.py`, `scripts/validate_package.py`, новую версию
   `scripts/create_issues.sh` и документацию 0.2.
4. Перенесите полезные собственные изменения из `skill/SKILL.md` в новый
   `plugins/fish-kp/skills/generate-fish-kp/SKILL.md`; затем удалите старый файл.
   Перед удалением проверьте diff, чтобы не потерять свои инструкции.
5. Объедините изменения README, `.gitignore`, CI и персональных ТЗ вручную.
   Свой lock-файл обновите командой `uv sync --extra dev` при необходимости.
6. `uv run pytest -v`; просмотрите `git diff`; откройте PR с ревью коллеги.

Если вместе с поставкой получен `upgrade-0.2.patch`, его можно сначала
проверить в корне старого репозитория:

```bash
git apply --check /path/to/upgrade-0.2.patch
git apply /path/to/upgrade-0.2.patch
```

При конфликте не применяйте патч принудительно: объедините изменения вручную.
Бинарный шаблон отдельно скопируйте из
`profiles/examples/fish_demo/template_kp.docx` в
`plugins/fish-kp/skills/generate-fish-kp/assets/template_kp.docx`.
Патч не содержит бинарные файлы и lock-файл, полученный в среде сборки.

## Если issues ещё не создавались

```bash
bash scripts/create_issues.sh OWNER/REPO --dry-run
gh auth login
bash scripts/create_issues.sh OWNER/REPO
```

Первый режим только показывает локальный план, не проверяет содержимое GitHub.
Второй создаёт недостающие задачи; существующие ищутся по точному ID в
начале заголовка и не меняются. Доступ к API обязателен для реального импорта.

## Если 50 issues уже импортированы

Обновлены Р1.1, Р1.3, Р1.5, Р1.6, Р1.7, Р3.0 и Р5.3.
Добавлены Р1.11, Р2.10, Р3.11 и Р5.9. Всего теперь 54 задачи.

```bash
# Новые задачи, без изменения старых:
bash scripts/create_issues.sh OWNER/REPO \
  --only Р1.11 Р2.10 Р3.11 Р5.9

# Посмотреть изменения семи существующих задач:
bash scripts/create_issues.sh OWNER/REPO --dry-run --update-existing \
  --only Р1.1 Р1.3 Р1.5 Р1.6 Р1.7 Р3.0 Р5.3

# После проверки применить:
bash scripts/create_issues.sh OWNER/REPO --update-existing \
  --only Р1.1 Р1.3 Р1.5 Р1.6 Р1.7 Р3.0 Р5.3
```

`--update-existing` заменяет заголовок и описание выбранных задач версией
из файлов. Старые заголовок/описание сначала сохраняются в
`out/issue-backups/<timestamp>/`. Комментарии и исполнители не редактируются;
существующие labels не удаляются. Если в описании уже есть важные изменения
команды, объедините их вручную вместо автоматического обновления.
Закрытые задачи не открываются заново автоматически.

Скрипт не настраивает Projects, не назначает исполнителей и не включает защиту
веток. В вашем приватном Free-репозитории ревью остаётся договорённостью команды.

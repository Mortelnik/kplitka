## 5. Финальная проверка перед передачей Р5

Выполнять из корня репозитория в PowerShell. Команды только читают
состояние файлов и не меняют исходный код.

``` powershell
# 1. Проверить текущую ветку и изменённые файлы
git status --short --branch

# 2. Проверить наличие основных документов
$required = @(
  "README.md",
  "docs/independent_installation.md",
  "docs/user_scenario_verification.md",
  "docs/demo_script.md",
  "docs/runtime_probe.md",
  "docs/plugin_guide.md",
  "docs/plugin_card.md",
  "docs/examples/README.md",
  "docs/examples/kp_without_volume_discount.docx",
  "docs/examples/kp_volume_discount.docx"
)

$missing = $required | Where-Object { -not (Test-Path $_) }
if ($missing) {
  Write-Host "ОТСУТСТВУЮТ ФАЙЛЫ:"
  $missing
} else {
  Write-Host "Все перечисленные файлы существуют."
}

# 3. Проверить относительные Markdown-ссылки из README и docs
# Этот поиск помогает найти кандидатов для ручной проверки;
# он не является полноценным валидатором Markdown.
Get-ChildItem README.md, docs -Recurse -File -Include *.md |
  Select-String -Pattern '\]\(([^)#]+)(#[^)]+)?\)' |
  ForEach-Object { "{0}:{1}: {2}" -f $_.Path, $_.LineNumber, $_.Matches[0].Value }
```

После вывода команды 3 проверить каждую локальную ссылку относительно
каталога файла, в котором она указана. Внешние URL проверять отдельно.
Не считать ссылку проверенной только потому, что она попала в список.

### Критерии завершения

-   [ ] Все перечисленные обязательные файлы существуют.
-   [ ] В README нет ссылок на отсутствующие файлы.
-   [ ] Относительные ссылки в Markdown проверены относительно
    правильных каталогов.
-   [ ] В документах нет неподтверждённых заявлений о runtime,
    интеграции, доставке файлов и готовности продукта.
-   [ ] Ограничения и зависимости от других участников явно обозначены.
-   [ ] `git status` просмотрен; в коммит не включены секреты, `.env`,
    `private_data/` и посторонние файлы.
-   [ ] Изменения не закоммичены и не отправлены без отдельного
    разрешения владельца задачи.

## 6. Итоговый статус

На момент подготовки этого чек-листа документационный комплект
Р5.1--Р5.7 подготовлен. Результаты независимой установки, тестов и
технического smoke-теста зафиксированы с ограничениями, указанными выше.

**Р5 нельзя считать подтверждением готовности полноценного продукта.**
Для этого необходимы результаты интеграционной проверки в целевой среде,
подтверждение передачи DOCX пользователю, согласованные бизнес-правила и
приёмка ответственными участниками.

Финальный статус Р5.8 выставляется после выполнения проверок раздела 5 и
фиксации фактических результатов, а не автоматически по факту создания
этого файла.

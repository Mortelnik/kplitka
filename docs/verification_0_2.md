# Проверки поставки 0.2

## Что проверено в среде сборки

- Установка зависимостей через `uv sync --extra dev`.
- Python 3.12.13 и 3.14.3: 17 тестов проходят в каждой версии.
- Копирование плагина в отдельную папку, запуск скрипта вне репозитория.
- Decimal: база 2000000.00, учебный налог 200000.00, итог 2200000.00.
- Создание читаемого DOCX, отдельное имя при каждом запуске.
- Негативные входы: float вместо строки, NaN, нулевой объём, отрицательная
  цена, неизвестные поля, ставка за пределами диапазона, битый JSON.
- Структура manifest/marketplace, пути ресурсов и metadata skill.
- `agentskills validate`: skill валиден.
- Ruff для нового кода и Bash syntax для wrapper: без ошибок.
- Импортёр: 54 уникальных ID; локальный dry-run; пропуск существующих issues,
  backup при обновлении, остановка на ошибке API проверены с подставными
  ответами, без реальных вызовов GitHub.
- Технический DOCX отрендерен и визуально просмотрен: текст и таблица читаемы.

## Что не проверено

- Установка и исполнение в Kalitka AI, возвращение скачиваемого файла клиентом.
- Создание/изменение issues в реальном GitHub-репозитории.
- Бизнес-расчёты контейнеров, скидок, остатков и налогов реальных товаров.
- Полный коммерческий шаблон с динамическими строками и реальными данными.
- Python 3.11 локально не запускался; он остаётся целевой версией workflow CI.

Локальный зелёный тест не является отметкой о выполнении бизнес-ТЗ.
Для проверки клиента используйте `docs/runtime_probe.md`.
